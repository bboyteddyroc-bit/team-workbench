# 中台设计基础规则

适用于 Seedance Hub 后续所有新增或调整的页面、功能、模块和组件。默认延续现有视觉与操作习惯，不以新增功能为由换肤、迁移框架或重构全站。

## 1. 先复用，再补公共能力
- 实现前检查现有相似页面及组件，明确复用对象。
- 按钮、输入框、筛选栏、标签页、弹窗、列表、分页和任务状态优先复用现有实现；禁止另造一套外观相近但细节不同的组件。
- 缺少组件时先补可复用的公共组件，再接入业务；避免模块专属补丁扩散。
- 新增依赖必须有实际必要性，不为保持风格迁移现有技术栈。

## 2. 视觉基线
- 沿用当前背景、面板、文字、强调色以及字体层级、间距、圆角和边框。
- 优先使用项目已有样式变量、公共类和组件接口，不猜测不存在的变量；必要的新变量定义在明确的公共位置。
- 不在业务模块散写独立颜色与大量覆盖规则；局部样式按模块作用域隔离，避免污染其他页面。
- 允许剪辑台等专用工作区保留已有信息密度与布局特征，统一不等于强制所有页面同一种布局。

## 3. 交互与状态
- 标题、操作区、筛选区、内容区按同类现有页面组织。
- 保持保存、搜索、分页、危险操作确认及提示方式一致。
- 覆盖加载、空数据、失败、成功、悬停、选中、禁用与键盘可见焦点状态；不能只实现有数据的默认态。
- 结果未知的提交先核查，不因界面错误自动重复生成或执行收费操作。
- 输入框、可编辑区、输入法和模态框保留输入行为；剪辑快捷键遵守 EDITOR_SHORTCUTS.md。

## 4. 性能与适配
- 无首屏依赖的模块评估按需加载；避免破坏初始化顺序、事件订阅、参数传递与失败重试。
- 列表媒体按可见性加载；不能擅自将卡片懒加载策略套到时间轴播放池。
- 窄面板、长文案、空状态均需检查；真实浏览器缩放不得用 CSS/viewport 缩放冒充。
- 不以拆分数量或删除样式数量作为优化目标，先有证据再改。

## 5. 交付验收
- 每次新增内容，交付范围包含：功能实现、组件复用、统一风格检查与相关回归。
- 与现有同类页面对照验收，检查视觉、布局、状态、焦点和响应式行为。
- 运行相关自动化检查；涉及公共组件时覆盖受影响页面。浏览器验收只报告实际执行结果，注明未测项。
- 按 AGENTS.md 同步功能说明，禁止把未实现功能记为可用。
- 项目当前是渐进形成的组件体系，不宣称已有完整标准化组件库；新增模块逐步补齐，不推倒重写。

## 变更原则
本规则为默认基线。用户明确要求新的视觉方向或特殊交互时，先说明与基线的差异及影响，再按确认后的需求执行；不静默改变其他模块。
