# TikTok 带货脚本框架 V1｜H-I-S-P-C × Commerce Beat Sheet

状态：项目生产规则；适用于已选定 Creative Concept 的 PRODUCTION_MODE。本文不产生新产品事实，也不把附件中的话术直接写入 Canonical Hook Library。

## 1. 决策顺序

默认生产顺序为 Creative Matrix → Production Package → Commerce Beat Sheet → TikTok Creator Spoken Script → Detailed Video Prompt。空间首帧和Storyboard仅在用户明确要求时制作。

H-I-S-P-C 是覆盖在**整条视频**上的转化检查层：H 停留、I 相关性、S 解决方案、P 可信证据、C 下一步。它不是五个等长章节，也不能改变 Beat Sheet 的时长、产品出现、Demo、证据和 CTA 时点。同一拍可以承担两个功能，例如首秒同时完成 H 与 I；一次可见 Demo 可以同时完成 S 与 P。

事实优先级仍为 Product Ground Truth > Approved Claims > Demo/Safety > Beat Sheet > Spoken Script > Detailed Video Prompt。若开头承诺在既有节奏内无法兑现，回到 Beat Sheet 修订并创建新的 Production Version；不得让口播或Prompt私自挪动节奏。

## 2. 从资料到可执行脚本的映射

| 层 | 必须回答的问题 | 输入 | 输出约束 |
|---|---|---|---|
| H Hook | 哪个目标用户为什么停下？ | Pain、Scenario、Hook、首帧可拍动作 | 0–3 秒只建立一个核心问题、结果或情境；声音与画面指向同一购买问题 |
| I Interest/Issue | 为什么和这个人有关？ | Character、关系、具体使用时刻 | 用一处具体细节完成代入，避免长期剧情铺垫 |
| S Solution | 产品怎样进入问题并发挥作用？ | Approved Claim、真实 Demo、使用限制 | 主卖点一句可懂；动作顺序和物体来源清楚 |
| P Proof | 观众能看见什么来相信它？ | Demo 状态变化、真实结果、已核实证据 | 每项承诺指向 Beat ID；优先展示过程和结果；不得虚构数据、亲测、评论或比较 |
| C CTA | 感兴趣的人下一步做什么？ | Production Package 的 `cta_mode` 和真实去向 | 一个主动作；与本条收益相关；无已知商品去向时不编造链接/商品卡 |

卖点的最小表达单元：**获批功能 → 当前用户情境 → 画面证据 → 可见结果**。先确定一个主卖点；辅助卖点只有在证据、时长和购买决策上确有增益时加入。功能词本身不能充当证据，情绪表演也不能替代 Demo。

## 3. 开头承诺与证据闭环

新口播的0–3秒按 `stable_script_generation_contract_v1.md` 第4节执行：先说具体目标用户身份，紧接产品对这类用户的最强已证实卖点或该人群最大具体痛点。两项共同指向一个购买问题，由后续证据兑现；仅环境声或用户明确指定原稿的例外按该节处理。

在写口播前，为每个 Hook 填一条可机器读取的 `promise_proof_map`：

```text
目标用户 + 具体触发 → 开头承诺/留下的问题
开头承诺 → 第一层可见兑现 Beat ID + 时间
开头承诺 → 完整兑现 Beat ID + 时间
每项功能/结果表达 → Approved Claim ID 或真实 Demo 来源
```

首 3 秒执行同一个信息目标：画面先出现与问题或结果有关的自然动作；口播补充观众看不出的意义；如果选用字幕，字幕只压缩这个信息目标。字幕不是必选，现有包稿默认无字幕。首帧动态应服务问题和产品，不能无关晃动。强开头应尽早得到第一层证据；无法兑现的悬念、时间承诺、折扣、对比、效果和“真实经历”不得使用。

示例：若开头承诺“这块垫上的玩具可以一起带走”，第一层证据是双手握两侧提手并抬起同一块垫，随后能辨认它成为可提的黑色包。单拍一个成品包不够证明“同一块垫变包”。

## 4. 45 秒 / 17+17+11 秒的节奏模板

以后每段最长17秒，三段合成一条45秒视频，不在每段重启H-I-S-P-C。具体时间只能由当前Beat Sheet决定；下表是审核目标，不是替代节奏表的新时间线。

| 段 | 商业任务 | H-I-S-P-C 覆盖 | 审核重点 |
|---|---|---|---|
| 0–17 秒 | 对的人停留，产品出现，核心 Demo 和首个结果尽早可见 | H + I + S + P1 | 开头一句承诺什么；最早哪拍证明；不把时间耗在介绍关系 |
| 17–34 秒 | 展开使用过程和第二层结果 | S + P2 | 状态连续、道具可追溯；画面解决购买疑问 |
| 34–45 秒 | 处理必要使用边界，强化最终结果，给行动出口 | P3 + C | 边界真实；结尾仍有产品价值；CTA 只有一个且去向真实 |

17秒切点允许明确地点硬切，但必须说明同一人、同一产品、同一批关键道具的继承状态。不得为承接五个字母加入冗长生活剧情。若真操作需要时间，优先保留Demo、删减口播；节奏仍装不下时回上游修订。

## 5. 文案和分镜的共同约束

- Beat Sheet 先定 Selling Track、Visual Track、Audio Track。Script和Detailed Video Prompt直接读取相同Beat Sheet ID、revision、SHA256；Prompt不通过口播倒推新节奏。
- 口播用自然美区达人语气；一句一意。画面负责动作，声音说明动作的意义、使用条件或购买理由。不要只把画面逐字念一遍。
- 关键动作需要连续可读，特别是产品/道具的来源、接触、状态变化、去向。AI Prompt 继承这些约束，不增添自动归位、凭空出现、未核实的机制。
- 每个声称的结果都标证据来源。视觉上能看到“这次演示发生了什么”，不自动推断普遍性能、容量、速度、耐用性或优于竞品。
- 口播价格遵守 Production Package：当前包项目 `price_mode=disabled`，口播不提售价，也不借“超便宜”等话术绕开核验。

## 6. 发布前审核与测试

审核 `hook_promise`、`target_viewer`、`proof_beat_ids`、`claim_ids`、`first_proof_sec`、`visual_voice_alignment`、`cta_mode`。下列任一失败即退回对应上游：开头吸引了与购买问题无关的人；承诺无对应证据；前 3 秒画面和声音各说一件事；主卖点没有可见过程/结果；CTA 去向不实。

做 Hook A/B 时，只变更一个核心开头变量，例如首帧动作、承诺角度或口播问法。保持目标用户、主卖点、Demo、主体证据、CTA、时长基本一致；记录差异与版本。复盘同时看首段停留、中段承接、目标用户互动、商品点击/后续业务信号；不能仅用播放量证明 Hook 有效。没有实测数据时只标“待测试”，不标“已验证”。

机器记录格式：[`hispc_beat_overlay.schema.json`](hispc_beat_overlay.schema.json)。此记录是 Production Output 侧的审核覆盖层，引用既有 Beat ID，不修改 Canonical Assets 或 Beat Sheet 本体。
