# TikTok 稳定脚本生成合同 V1

状态：PRODUCTION_MODE 项目规则。适用于用户已经选定 Creative Concept 后，稳定生成 Commerce Beat Sheet、达人口播和后续分镜。本文不新增产品事实，不替代 Commerce Beat Sheet。

## 1. 唯一生产顺序

```text
Production Package
→ Hook 选择与承诺校验
→ Commerce Beat Sheet
→ H-I-S-P-C 覆盖审核
→ TikTok Creator Spoken Script
→ Detailed Video Prompt
```

空间首帧和Commerce Fast-Cut Storyboard默认跳过；只有用户明确要求时恢复。Detailed Video Prompt必须直接继承Beat Sheet与口播，并按`direct_video_prompt_contract_v1.md`补齐空间、机位、光线、动作和连续性。

Commerce Beat Sheet 仍是唯一节奏真相。本文负责固定“说服顺序”和输出格式；具体秒数、产品首次出现、Demo、结果与 CTA 时点由当前 Beat Sheet 决定。

每条新脚本至少安排两次人物正对镜头同期说话，通常一次讲关键产品利益、一次完成结尾CTA；台词必须符合角色身份与拍摄者关系。口播尽量覆盖当前产品已批准、在该条视频中能以画面支持的主要卖点。先删重复句和空泛转场，再提高信息密度；每个镜头最长3秒，切镜跟着台词语义与动作变化，不靠不可听清的语速硬塞卖点。

## 2. 每条视频先冻结的输入

没有以下信息时，不得用营销话术补齐：

| 输入 | 规则 |
|---|---|
| `primary_promise` | 一条视频只证明一个主要购买结果 |
| `target_viewer` | 明确谁会遇到这个问题 |
| `role_contract` | 锁定身份、年龄阶段、与拍摄者关系、消费动机和对白前提 |
| `traditional_solution` | 观众当前使用的真实方案；没有证据时写“未设定”，不能贬低虚构竞品 |
| `traditional_problem` | 传统方案在当前场景中的具体可见问题 |
| `switch_reason` | 为什么产品能自然进入，不得写成无证据亲测或推荐 |
| `visible_benefit` | 展开或操作后，镜头能够直接看到的利益 |
| `demo_object_list` | 逐个装入、处理或测试的物品；每项必须能在画面中追踪 |
| `product_reveal` | 产品形态、结构或工作状态的清晰展示 |
| `result_confirmation` | 可见终态或人物确认，不把单次演示夸大为普遍性能 |
| `cta_mode` | 当前真实入口，如 TikTok 小黄车；没有入口则不能编造 |
| `approved_claim_ids` | 每项功能、比较、结果对应的已批准事实 |

### Role Contract 硬锁定

同一脚本只能替换不改变语义的演员外观、发型、肤色、体型和兼容服装。主角身份、年龄阶段、生活状态、与拍摄者关系、消费动机及对白前提不可直接替换。妈妈换成年轻女孩、员工换成顾客、情侣换成朋友等均触发 `SCRIPT_VARIANT_REQUIRED`，必须重新审核口播逻辑。

## 3. 默认销售链

这是视觉 Demo 商品的默认结构。Beat 可以合并，但不得跳过承诺所需的证据。

| 顺序 | 固定模块 | H-I-S-P-C | 观众当前问题 | 画面任务 | 口播任务 | 下一拍滑梯 |
|---:|---|---|---|---|---|---|
| 1 | Hook 承诺 | H | 我为什么要停下？ | 首帧直接呈现与目标用户及主利益/痛点对应的动作 | 0–3秒连续完成：先点明具体用户身份，再说最强已证实卖点或该人群最大具体痛点 | 让我想知道这个产品如何解决我的问题 |
| 2 | 传统方案出现的问题 | I | 这是不是我遇到的麻烦？ | 展示一个可见问题及其后果 | 说清成本、麻烦、浪费或限制，只说已证实内容 | 既然旧方法有问题，她改用了什么？ |
| 3 | 为什么改用这个产品 | S | 它为什么适合当前场景？ | 产品由明确来源进入画面并开始正确使用 | 用一句话连接问题与主卖点 | 它展开或开始工作后到底能带来什么？ |
| 4 | 展开后的可见利益 | S+P | 这个卖点能不能看见？ | 展开、铺平、连接、启动或状态变化 | 解释动作带来的使用利益，不逐字复述动作 | 它能否处理真实数量或真实任务？ |
| 5 | 装入物品列表 / 累积 Demo | P | 实际使用时够不够、顺不顺？ | 物品逐个进入；来源、位置、数量连续可追踪 | 按购买意义分组，不机械报菜名 | 东西都进去后，产品怎样完成最后一步？ |
| 6 | 产品展示 | P | 产品如何从工作状态进入完成状态？ | 清楚展示产品结构、关键动作和物体去向 | 强调使用方式或差异化设计 | 最终结果是否真的成立？ |
| 7 | 结果确认 | P / Reward | 承诺兑现了吗？ | 给终态、人物轻反应或明确对比 | 用一句短句确认最初承诺 | 如果这正是我的问题，下一步是什么？ |
| 8 | CTA | C | 我现在去哪里行动？ | 指向真实商品卡/小黄车，产品仍可见 | 回扣原问题与主要结果，只给一个动作 | 结束或自然回环首帧 |

`demo_object_list` 适用于容量、收纳、清洁、工具、烹饪等可累积证明的商品。其他商品用同位置的 `proof_unit_list`：逐项加入可见证据，而不是虚构装入物品。

## 4. Hook 选择系统

### 前三秒口播硬规则（2026-10-16用户指定）

未来新写或允许改写的带货口播，必须在0–3秒内按顺序连续说完两项信息：**具体目标用户身份 → 产品对这类用户的最强已证实卖点，或这类用户的最大具体痛点**。这一规则适用于下列各类Hook，必须落到实际台词，不能只写在目标用户说明或用画面代替说出身份。

- 身份使用明确人群、角色或生活情境，例如带孩子出门的妈妈、常去野餐的人、有橡树庭院的屋主；“大家”“姐妹们”“你们”单独出现不算具体身份。
- 第二项二选一：一个最强且有产品事实支持的使用利益，或一个该人群能立即理解的具体麻烦。“最强/最大”是策划选题标准，不要求台词使用最高级，不得虚构排名、性能或普遍用户结论。
- 两项属于同一个购买问题，紧接表达，不插入问候、自我介绍、无关剧情或第三个卖点。按可听清的目标语速估时，超出3秒先精简措辞，不能仅在时间表上标成3秒。
- 开场画面同步展示所说的人群情境、痛点或利益，后续Demo兑现同一个主承诺。
- 用户明确要求无口播/仅环境声时不新增台词；明确要求逐字保留原稿或指定特殊开头时，按当前用户指令执行并记录例外，不擅自改词。历史生产版本不回改。

默认句式：`[具体用户身份], [最强已证实利益 / 最大具体痛点].` 不要求每条都使用相同语法。

用户提供的《TikTok黄金开头》是候选素材源，不是已验证 Hook Library，也不自动成为产品事实。每条视频只选一个 `hook_family`、一个主要注意力问题和一个首帧动作。

### A档：可优先使用的证据型 Hook

| Hook family | 适用条件 | 首帧滑梯画面 | 必须兑现的证据 |
|---|---|---|---|
| `SCENE_PROBLEM` 场景痛点 | 问题可拍 | 旧方法正在失败或产生麻烦 | 产品在同一场景解决问题 |
| `ACTION_IMPACT` 动作冲击 | 核心卖点可由一个动作启动 | 手已抓住、拉开、倒置、按下或开始操作 | 完整动作链和终态 |
| `VISUAL_CONTRAST` 视觉对比 | Before/After条件一致 | 同框或快速切换两个状态 | 中间过程与真实结果 |
| `SUSPENSE_TEST` 悬念测试 | 结果可以现场证明 | 测试已开始但未完成 | 不拖延的可见结果 |
| `DIRECT_PAIN` 直说痛点 | 人群和问题明确 | 问题主体占画面中心 | 对应解决过程 |
| `TUTORIAL` 教程式 | 使用方法本身有价值 | 错误或麻烦步骤立即出现 | 正确操作与结果 |
| `RESULT_FIRST` 结果先行 | 能回溯证明来源 | 先给完成结果，再切回过程 | 同一产品、同一任务的完整过程 |
| `DIRECT_DIALOGUE` 对镜对话 | Role Contract 与台词一致 | 人物在事件中对同行拍摄者说话 | 后续行动证明所说内容 |
| `THREE_REASONS` 三个理由 | 时长能容纳三个独立证据 | 首个理由直接可见 | 每个理由均有对应证据；不只列功能 |
| `UNEXPECTED_RESULT` 意外结果 | 反应有真实可见来源 | 人物看到结果而自然停顿 | 镜头给出造成反应的结果 |

### B档：只有证据充分才可使用

- `PRICE_COMPARE`、`VALUE_COMPARE`：要求同条件比价证据，且 `price_mode=enabled`。
- `COMMON_MISTAKE`、`INFORMATION_GAP`、`COUNTERINTUITIVE`：要求能够证明旧方法的问题和新方法成立，禁止泛称“你一直做错了”。
- `PERSONAL_EXPERIENCE`、`30_DAY_TEST`、`HONEST_FLAW`：必须有真实经历、时间或缺陷依据。
- `CONSEQUENCE_WARNING`：后果必须真实、合规并与产品能力直接相关。
- `DRAMATIC_CHALLENGE`：不得牺牲安全或用极端测试冒充日常性能。
- `IF_I_WERE_YOU`、`EXPERIENCE_SUMMARY`：说话者身份和经历必须与 Role Contract 一致。

### C档：默认禁用，核实后才能解锁

- 系统价格错误、最低价、商家不赚钱、平台把价格打下来。
- 即将停产、快没货、终于补货、限时优惠或优惠券。
- 无依据的“大公司隐瞒”“商家骗你”“所有产品都一样”。
- 虚构亲测、退货原因、兽医/专家结论、用户评价和健康后果。
- 声称传统方案与本产品“效果完全一样”或产品优于竞品，但没有同条件证据。

## 5. 口播滑梯效应

滑梯效应不是每句故意留悬念，而是让每拍完成当前信息后，自然打开下一项购买问题。

每个 Beat 使用以下结构：

```text
Answer：回答上一拍的问题
Value：说明这个画面对用户意味着什么
Handoff：把注意力交给下一项尚未证明的内容
```

允许的 Handoff：

- 问题 → 后果：`And the worst part is...`
- 后果 → 产品：`So I switched to this.`
- 产品 → 展开利益：`But this is the part that sold me.`
- 展开利益 → 累积证明：`Now watch what actually fits.`
- 累积证明 → 完成动作：`Once everything is on it...`
- 完成动作 → 结果：`And that's the whole point.`
- 结果 → CTA：回扣原问题并指向真实入口。

这些只是逻辑，不要求逐字使用。禁止一拍同时抛出多个新问题；最多一个主要注意力锚点和一个辅助锚点。画面已经明确展示动作时，口播说明利益、后果或购买理由，不念动作说明书。

## 6. 45秒与17秒分段

以后45秒默认按17+17+11秒承载一条完整销售链，不在每段重新开场。

| 区间 | 默认任务 | 必须到达的状态 |
|---|---|---|
| 0–17秒 | Hook、传统方案问题、改用产品、启动第一层 Demo | 产品已经出现，第一层承诺开始兑现 |
| 17–34秒 | 展开后的可见利益、物品/证据逐项累积；12–18秒附近可设置Secondary Stop | 中段持续增加新证据，不重复第一卖点 |
| 34–45秒 | 产品完成动作、结果确认、CTA | 主承诺先被证明，再引导点击小黄车 |

40秒等非17秒整数时，按每段最长17秒切分，例如17+17+6秒。动作声和结果停留优先于塞满口播。

## 7. 每次固定输出

每个新脚本必须按同一顺序交付：

1. **Input Lock**：产品事实、Approved Claims、Role Contract、场景、CTA、禁用表达。
2. **Hook Decision**：选用类型、目标观众、首帧、开头承诺、第一兑现与完整兑现 Beat。
3. **Attention Spine**：`The viewer keeps watching to discover ______.`
4. **Commerce Beat Sheet**：唯一节奏来源；含 Selling / Visual / Audio track。
5. **H-I-S-P-C Map**：H/I/S/P/C分别落到哪些 Beat，并列 `promise_proof_map`。
6. **Beat-Aligned Script**：时间、Beat ID、画面任务、人物口播/No VO、滑梯 Handoff、证据。
7. **Clean English Read**：只有可直接朗读的自然美式英文。
8. **Delivery Notes**：语速、停顿、重音、同期声、每段词数。
9. **Proof & Continuity Check**：产品来源、动作顺序、物体去向、Before/After、角色身份。
10. **CTA Check**：真实入口、一个动作、无虚假紧迫感。

## 8. 机器校验失败条件

出现任一项即退回相应上游，不生成最终故事板：

- Hook 没有具体目标用户或可见承诺。
- 有口播且无用户指定例外时，前三秒未按“具体身份→主利益或具体痛点”的顺序连续说完；仅泛称人群、身份只出现在画面中或靠不可听清语速硬塞，均退回改写。此项需核对实际台词与读速，不视为仅靠文本结构校验即可通过。
- Hook 的第一兑现和完整兑现找不到 Beat ID。
- 传统方案问题来自想象，或比较条件不一致。
- 主卖点没有完整的 `before → operation → working evidence → result`。
- 物品凭空出现、重复出现、自动归位或装入后又留在台面。
- 产品结构、使用顺序或终态违反 Product Ground Truth。
- 口播人物身份与 Role Contract 不一致。
- 为换演员而改变母亲、年轻女性、员工、顾客等身份。
- CTA 出现在主承诺证明之前。
- 价格、折扣、库存、时限、亲测、数据或健康结果未经批准。
- 画面、口播、字幕在前三秒表达三个不同重点。
- 下游脚本、故事板或 Prompt 改变 Beat Sheet 的节奏和卖点顺序。

## 9. A/B 测试约束

同一主体一次只替换一个 Hook 变量：首帧动作、承诺角度或开头口播三者选一。保持目标观众、Role Contract、传统问题、主卖点、Demo、主体证据、CTA和时长不变。没有真实投放数据时标记 `UNTESTED`，不得写“已验证有效”。
