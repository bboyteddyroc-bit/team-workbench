# 什么是H\-I\-S\-P\-C 万能脚本框架

## **H\-I\-S\-P\-C **

**1\. 这是什么**

H\-I\-S\-P\-C 是一套用于短视频口播、带货视频、广告脚本、达人沟通内容的通用表达框架。

它的核心作用不是“把话说完整”，而是按用户决策顺序组织信息：

先停留 \-\> 再共鸣 \-\> 再理解方案 \-\> 再建立信任 \-\> 再触发行动

对应五个模块：

- H Hook：抓住注意

- I Interest / Issue：激发兴趣或点出问题

- S Solution：给出解决方案

- P Proof：提供证据

- C CTA：推动行动

## **2\. 核心认知**

这不是一个“文案格式”，而是一套“转化顺序”。

用户通常不会因为你信息完整就行动，而是会按下面这条心理链路往下走：

1\. 我为什么要停下来？

2\. 这件事和我有什么关系？

3\. 你到底想表达什么方案？

4\. 我凭什么相信你？

5\. 那我下一步该做什么？

H\-I\-S\-P\-C 的价值就在于，它把这五个问题按顺序回答掉。

## **3\. 五个模块怎么理解**

**H = Hook 抓注意**

目标：让对的人愿意继续看。

常见方式：

- 结果型：直接亮结果

- 痛点型：直接点问题

- 反差型：打破原有认知

- 好奇型：制造信息缺口

- 场景型：让目标用户一眼代入

判断标准：

- 前一句有没有把人拦下来

- 目标用户能不能立刻知道“这条是说给我听的”

- 开头是不是具体，而不是空泛

常见误区：

- 只有情绪，没有对象

- 只有夸张，没有问题

- 一上来讲产品参数

**I = Interest / Issue 激兴趣或戳痛点**

目标：让用户感觉“这事和我有关”。

这里可以有两种写法：

- Interest：放大好处、结果、收益

- Issue：放大问题、损失、错误代价

在实操里，这两者通常可以合并成一段。

判断标准：

- 用户是否被明确代入到一个真实场景

- 用户是否意识到“不解决会有损失”

- 这一段是不是在说用户，而不是在说你自己

常见误区：

- 只讲大道理，不讲具体场景

- 只讲问题，不讲影响

- 问题不够尖锐，导致后面的方案没有必要性

**S = Solution 给方案**

目标：把你的方法、产品、机制、动作清楚说出来。

可用写法：

- 给方法：告诉用户怎么做

- 给产品：告诉用户用什么解决

- 给机制：解释为什么这个方案有效

- 给步骤：降低理解门槛

判断标准：

- 用户能不能一句话听懂你的方案是什么

- 用户能不能知道“为什么这个方案有用”

- 方案是不是足够简单，能被快速接受

常见误区：

- 讲太长，进入教学状态

- 方案太虚，像口号

- 没讲清楚方案和前面问题的对应关系

**P = Proof 证可信**

目标：解决“我凭什么信你”。

可用证据：

- 数据

- 前后对比

- 用户反馈

- 真实案例

- 产品细节

- 使用过程

- 第三方背书

判断标准：

- 这段证据能不能降低用户怀疑

- 证据是不是具体，而不是空泛自夸

- 证据是不是和前面的方案强相关

常见误区：

- 只有“很多人都在用”这种空证明

- 证据和问题无关

- 先证明自己很厉害，但没有证明方案有效

**C = CTA 促行动**

目标：告诉用户下一步做什么。

常见动作：

- 评论

- 私信

- 点击商品卡

- 点链接

- 领取资料

- 关注账号

- 下单购买

判断标准：

- 动作是否明确

- 动作是否只有一个主目标

- 用户是否知道做完之后能得到什么

常见误区：

- 没有 CTA

- 一条视频塞多个 CTA

- 只让用户行动，但没讲行动后的收益

## **4\. 整体逻辑**

这套框架的本质不是五段话，而是一条推进链：

Hook 把人留下 \-\> Interest / Issue 让人产生关系感 \-\> Solution 给出答案 \-\> Proof 建立可信度 \-\> CTA 推动转化

如果拆成业务语言，可以理解成：

- H 解决停留

- I 解决代入

- S 解决理解

- P 解决信任

- C 解决行动

## **5\. 最适合用在什么地方**

高适配场景：

- TikTok Shop 带货口播

- 短视频广告脚本

- 达人种草视频

- 产品卖点表达

- 直播切片视频

- 评论区引流文案

也可用于：

- 销售话术

- 达人邀约话术

- 页面首屏文案

- 训练团队写脚本

## **6\. 为什么它适合 TikTok Shop**

TikTok Shop 场景下，内容不是只求“讲明白”，而是要同时完成：

- 抓住人

- 筛对人

- 激发兴趣

- 建立信任

- 推动点击和下单

所以这套结构很适合短视频带货，因为它天然贴合转化链路，而不是单纯写文案。

对团队来说，它还有一个额外价值：

- 新人容易学

- 脚本容易复盘

- 不同产品也能复用同一套结构

- 更适合沉淀成标准模板

## **7\. 实操判断法**

拿到一条脚本时，可以用这五个问题快速检查：

1\. 开头有没有把人抓住？

2\. 用户有没有被带进问题或需求里？

3\. 方案有没有说清楚？

4\. 证据够不够让人相信？

5\. 最后有没有明确动作？

如果五个问题里有两个以上答不上来，这条脚本通常就不稳。

## **8\. 常见误区**

- 只会写 Hook，不会往后推进

- 问题讲得很重，但方案很弱

- 方案讲完就结束，没有 Proof

- 有 Proof 但没有 CTA

- 每段都写了，但顺序混乱

- 为了“完整”把视频写得太长

要点不是每一段都写很多，而是每一段都承担清楚自己的任务。

## **9\. 万能填空模板**

**模板 1：通用带货口播**

H

你是不是也有这个问题？

I

很多人一直没解决，不是因为产品不行，而是因为方法用错了。

S

更有效的做法是用这个方案，它的核心是 \_\_\_\_\_\_\_\_。

P

为什么有效？因为它能做到 \_\_\_\_\_\_\_\_，而且很多真实用户用了之后会出现 \_\_\_\_\_\_\_\_ 的变化。

C

如果你也想解决这个问题，点这里 / 评论区留词 / 直接下单。

**模板 2：问题放大型**

H

你现在做不起来，可能不是不努力，而是一开始就做错了。

I

大多数人卡在 \_\_\_\_\_\_\_\_，结果就是 \_\_\_\_\_\_\_\_。

S

真正该改的不是 \_\_\_\_\_\_\_\_，而是 \_\_\_\_\_\_\_\_。

P

因为当你把这里改掉之后，通常会直接影响 \_\_\_\_\_\_\_\_。

C

想看完整做法，留言“模板”。

**模板 3：产品卖点型**

H

如果你最在意的是 \_\_\_\_\_\_\_\_，那这个东西你可以看一下。

I

很多同类产品的问题是 \_\_\_\_\_\_\_\_，所以用起来总会 \_\_\_\_\_\_\_\_。

S

这个产品真正有价值的点在于 \_\_\_\_\_\_\_\_。

P

它不是单纯“看起来不错”，而是在 \_\_\_\_\_\_\_\_ 这个场景里确实更好用。

C

需要的话直接点商品卡看详情。

## **10\. 一句话总结**

H\-I\-S\-P\-C 不是写稿公式，而是一条用户转化路径：

先抓住，再代入，再给答案，再给证据，最后推动行动。

如果团队要把它真正用起来，最好的方式不是背定义，而是把它做成固定脚本检查表和可填空模板。
