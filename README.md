# Seedance 团队工作台

第一版面向公司内网或 VPN。支持公司共享账号池、成员管理、每组 1–10 条批量任务、多组提示词、4–15 秒参数、并发队列、失败原因、预览与下载。接入的是已有 TikTok 网页会话的内部接口，不是已获官方长期授权的公共 API。

## 本机使用

在此目录运行 `python -B app.py`，打开 http://127.0.0.1:8765 。首次由本机用户创建管理员；当前交付环境已按用户要求创建 jinn，没有把密码写入文件。

管理员在“团队成员”添加同事账号。同事首次登录需修改初始密码。在“账号连接”粘贴完整的创建请求 cURL；此操作只查询平台来验证连接，不会生成视频。只允许管理员创建公司共享连接，不再提供个人 TikTok 账号连接。员工保留工作台登录，管理员可查看公司共享任务。

## 这台 Windows 电脑作为执行机

当前检测到内网 IPv4：192.168.100.10。地址变化后需重新生成服务器证书并调整启动参数。

运行环境：Python 3.11+，依赖见 requirements.txt。当前电脑已具备依赖。代理默认为 http://127.0.0.1:7890，执行机需维持代理和 TikTok 网络连接；用 HUB_PROXY 环境变量修改，设为空使用系统默认代理发现。

### HTTPS 内网入口

1. 生成本机专用证书：`python -B lan.py --host 192.168.100.10 --prepare-only`。
2. 在同事电脑上，由用户或 IT 将本目录的 `seedance-hub-ca.crt` 安装到受信任根证书颁发机构。只分发该公钥证书，绝不分发 state 目录中的私钥或数据库。部署前核对生成命令打印的 SHA256 指纹。
3. 启动：`python -B lan.py --host 192.168.100.10`。访问 https://192.168.100.10:8443 。程序不会自动改变证书信任库或 Windows 防火墙。
4. 如果同事无法连接，管理员可为 TCP 8443 添加仅限 Private/Domain 配置文件、LocalSubnet 来源的入站规则；VPN 网段需要由 IT 另行指定范围。不要开放到公网。

Windows 证书安装可以使用证书管理器，也可在确认公钥证书来源后执行 `certutil -user -addstore Root seedance-hub-ca.crt`。这会增加该本机 CA 的信任；移除时根据证书名称在当前用户证书管理器删除。程序不代替用户执行。

内网 TLS 进程负责执行队列，必须保持运行。最多一个进程运行 worker。需要同时保留 localhost 管理页时，启动本机页之前设置 `$env:HUB_WORKER='0'`；这个本机页只处理 UI/API，内网进程执行任务。不要使用多个 Uvicorn worker。

## 额度与失败

只有点击“提交生成”才会创建任务并使用平台额度。每个已验证连接最多同时执行 10 条任务；这不控制在 TikTok 网页直接创建的任务。中台每日提交限制已取消，旧数据库字段仅为兼容保留、不再生效。中台不宣称知道实际平台剩余额度。

提交结果不明时不会自动重试，且阻塞该账号后续排队任务。核对网页后可关联相同提示词、提交时间匹配的任务；管理员也可关闭追踪（不取消平台任务）。执行错误可在恢复连接后“同步状态”。超过两小时未完成的任务进入“需要处理”，避免无限轮询。

视频成功后自动缓存为本机 MP4。访问缓存仍校验任务权限，不向用户公开整份账号历史。磁盘文件不会自动删除；管理员应定期检查空间。页面支持加载更早任务。

## 数据与凭据

state/ 下包含 SQLite 数据库、加密密钥、视频缓存、TLS 私钥和 worker 锁。Cookie/CSRF 在数据库内加密，密钥同机保存；拥有执行机文件权限的系统管理员仍可解密。使用专用 Windows 用户运行，并将 state 目录 ACL 限制给该用户和系统管理员。应用不自动修改系统 ACL。

不要把 state/、原始 cURL 文件、真实提示词记录或私钥放入共享代码仓库。备份须同时保留数据库和密钥。登录会话有效期 8 小时。凭据过期需要重新连接；没有自动登录、刷新平台凭据、SSO、跨机器队列和高可用能力。

## 验证

`python -B -m unittest test_hub` 运行独立临时数据库与 FakeProvider 测试，不使用真实额度。`node --check static/app.js` 检查前端语法。

界面 QA 在隔离演示实例中运行；演示记录不导入实际团队数据库。官方 API 权限、团队长期并发可用性仍需单独核实。

## 新编辑器与接通状态（2026-10-19）

全能模式支持最多 9 张参考图、3 段视频、3 段声音，总计最多 12 个素材。视频和声音各自累计最长 15 秒，单段至少 2 秒；声音必须搭配图片或视频。此限制来自用户抓包中的网页代码，覆盖原先 10 张图的设计目标。单文件中台上限 64 MB。首尾帧需要首帧，尾帧可选。

已实现：2.0 文生视频；2.0 / Mini / Fast 全能参考；2.0 首尾帧；同一登录的子账号池；提交前额度检查。自动模式先尝试各子账号的 2.0，参考素材任务额度不足时再选择 Mini、Fast。无素材文生视频及首尾帧目前只使用 2.0，不推测未确认的 Mini/Fast 接口。

2026-10-20 已只读验证三个子账号的身份和额度，并同步到公司账号池。管理员可在账号池点击“同步子账号”刷新加密连接。账号选择通过独立请求 Cookie 的 s_aio_client_id 完成，不改变原网页登录。素材缓存按账号隔离。

@图片编号按当前素材顺序转成网页原生 <|media:N|> 标记。视频和声音使用平台返回的 vid，图片使用已确认的 ImageX 地址。视频上传使用抓包中合并提交的 VOD multipart 协议；公司 Cookie/CSRF 不发送到存储域名，但该协议要求将临时上传 STS 放入 post_upload_req。

验证边界：旧 Mini 请求来自已受理 HAR；图片上传曾实际成功。新模式、媒体上传及首尾帧已按网页代码和 HAR 适配并通过隔离测试，没有新建收费视频任务，因此仍待实际生成验收。HTTP 超时或返回任务 ID 不明时不会自动重提；版权/内容审核失败不会触发账号或模型切换。


## 内置剪辑台（2026-10-20）
生成结果旁点击“剪辑”，或打开左侧“剪辑台”。左侧选择已完成的视频加入时间轴；拖动片段排序，选择片段后调整入点/出点、分割或设置音量。可保存多个项目，添加定时文字字幕，上传一条配音/背景音乐。支持 9:16、16:9、1:1 等比适配补黑边，导出 720 级、24fps、H.264/AAC MP4。第一版不包含关键帧、动画转场、自动字幕或画面自由裁切。

项目与导出按成员隔离；管理员沿用现有共享账号视频查看权限。原片不修改。项目最多 50 段、10 分钟、100 条字幕，单成员最多 3 个待导出任务。FFmpeg 独立线程按单任务排队、每次编码限制 2 线程。导出快照不会因继续编辑项目而改变。服务重启中断的导出标记失败，可重新导出。

上线前快照位于同级 seedance-hub-snapshot-20261020-103337/snapshot.zip，含校验清单与 SQLite 一致性备份。运行该目录 restore.py 可只验证；停止服务后使用 python restore.py --apply 恢复原代码，再重新启动。默认不覆盖 state，因此新增任务、视频、账号和剪辑项目数据保留；完整数据恢复应另行明确范围。

验证：本地 FFmpeg 合成测试验证裁剪、双片段拼接、中文烧录字幕、音频混合、尺寸/时长、项目隔离、版本冲突和导出幂等。浏览器自动化被当前 Work 设置关闭，未完成浏览器拖动和响应式视觉验收。

## 图片自动分类修复与启用

- 自动分类与右下角 AI 助理共用 Agnes 连接。管理员在 AI 助理 → 连接设置中保存 API Key 后，从未识别过的历史图片会转入队列；已有有效配置的旧数据库在新版本加载时也会补入队列。配置存在不等于密钥、余额或图片输入能力已经验证。
- 新上传图片自动排队；视频和音频仅按文件类型归档。图片分类为人物、产品、场景、其他。识别会向 Agnes 发送最大 1024 像素的 JPEG 副本，可能消耗 AI 额度。
- 手动分类优先。明确 HTTP 429 限流时，整个图片分类队列暂停，按 1、2、4、8、16、32、60 分钟退避（之后每次最长 60 分钟；若服务端 Retry-After 更长则遵守该时间），到期自动尝试；成功后恢复，每张成功后间隔至少 5 秒。冷却和连续限流次数保存在 SQLite，重启仍有效；已记录为“AI 服务限流”的历史失败也会恢复等待，首次至少等待 1 分钟。不会批量同时重提。网络超时、余额/密钥错误、无效答案及服务重启中断不会自动重试。手动分类不会被重试覆盖。素材页和参考弹窗每 3 秒刷新，显示“服务限流 · 等待后自动继续”。中台 worker 必须保持运行才能自动处理。
- 修改 Python 后必须重启旧进程才能生效。应先确认现有任务已结束，再停止旧进程；不要启动第二个 worker。已有待识别图片会在新 worker 启动后自动调用 AI，建议先确认余额。
- 本机使用 `./start.ps1`，它显式使用项目 `.venv`。内网执行入口使用 `./.venv/Scripts/python.exe -B lan.py --host 192.168.100.10`。若同时保留本机入口，请沿用上文 `HUB_WORKER=0` 的配置；不要更改既有 HUB_STATE/HUB_ORIGIN。
- 模型格式实测：仅设置较小 `max_tokens` 会出现 HTTP 200、`finish_reason=length`、`content` 为空而存在 `reasoning_content`。分类请求现显式设置 `chat_template_kwargs.enable_thinking=false`，保留 2048 token 上限；同一张图片真实返回 `finish_reason=stop`、`content=person`，解析成功。只读取最终答案，不从推理文本猜测分类；支持纯类别、JSON category、代码块及文本内容块，截断/拒绝/歧义答案明确报错且不自动重试。参数依据：[Agnes 2.5 Flash 官方文档](https://wiki.agnes-ai.com/zh-Hans/docs/agnes-25-flash.md)。
- 隔离回归：`./.venv/Scripts/python.exe -B -m unittest -v test_asset_classification test_hub`；分类测试不访问真实图片、密钥或外部网络。
